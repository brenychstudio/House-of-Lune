# BR-04 Customer Identity and Collector Space implementation plan

**Goal:** Add a provider-neutral, PostgreSQL-backed customer identity and Collector Space foundation on `feature/br-04-identity` without starting checkout, production delivery, WebAuthn ceremonies, or spatial runtime work.

## 1. Domain contracts and security primitives

- Add failing unit tests for email normalization, customer lifecycle transitions, challenge/session state, address validation, order ownership, guest-order claim eligibility, opaque token hashing, and cookie policy.
- Implement pure customer-domain contracts and Web Crypto-compatible 256-bit opaque-token helpers.
- Keep domain code independent of Next.js, PostgreSQL, Cloudflare, and providers.

## 2. PostgreSQL identity foundation

- Add migrations `0011–0013` for guest/auth sessions, passwordless challenges, identity hardening, address timestamps, and passkey-ready public credential storage.
- Update schema/checksum verification for the new tables, constraints, indexes, and triggers.
- Add failing real-PostgreSQL integration tests for invitation/activation, token hashing and concurrency, session expiry/revocation, identity conflicts, address ownership, order ownership/claim, passkey uniqueness, forward migration, and empty bootstrap.
- Implement focused repositories and transactional application services using existing transaction/audit primitives.

## 3. Passwordless and Collector Space application surface

- Add provider-neutral passwordless delivery contract with an in-memory test adapter and a tightly gated development harness that never logs or persists raw tokens.
- Add request, exchange, logout, and owner-scoped address Route Handlers with generic public responses, clean redirects, no-referrer/private-cache headers, and centralized cookies.
- Replace `/[locale]/account` placeholder with request-time authenticated/unauthenticated/degraded semantic states and truthful empty sections.
- Add test-only E2E setup endpoints gated to the test environment; never activate them in staging/production.

## 4. Verification and closure

- Add unit, PostgreSQL concurrency/invariant, E2E, accessibility, cookie, replay, outage, and token-leak checks.
- Document the identity contract, Collector Space/spatial boundary ADR, QA evidence, result packet, roadmap status, and BR-05 entry criteria.
- Run fresh install/audit/lint/typecheck/unit/integration/E2E/build/db-check/diff-check and local OpenNext/Cloudflare smoke verification.
- Create coherent commits, push `feature/br-04-identity`, and open a Draft PR targeting `feature/br-03-catalog`; do not merge or deploy.
